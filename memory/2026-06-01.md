# 2026-06-01 — CherryOne v2.1.3 GPIO Buzzer/LED Fix

## Session Summary
Debugging GPIO32 (pump LED) and GPIO33 (buzzer relay module) behavior.
Multiple issues found and fixed in v2.1.3.

## Issues Found & Fixed

### Bug 1: GPIO32 LED + GPIO33 Buzzer stuck ON after V0 Stop
- **Root cause:** `stopSystemAndVerifyAll()` sends Modbus OFF directly via `RTU_MASTER.writeHoldingRegister()`, bypassing `writeRelay()`. The `relayState[1]` array was never cleared, so Task3's buzzer/LED FSM still thought the pump was ON.
- **Fix:** `stopSystemAndVerifyAll()` now clears all 21 `relayState[]` entries + force-sets GPIO32 LOW + GPIO33 HIGH.

### Bug 2: GPIO33 relay module LED always ON (never off)
- **Root cause:** `pinMode(x, OUTPUT)` on ESP32 Arduino Core 1.0.6 defaults output to LOW. With active-low optocoupler relay module (LOW = ON), calling `pinMode` before `digitalWrite` energizes the relay before the OFF command arrives.
- **Fix:** Reordered to `digitalWrite(HIGH)` BEFORE `pinMode(OUTPUT)` in both `bootRelaySafety()` (main.cpp) and Task3 init (33_Tsk3.h).

### Buzzer timing change
- Changed from 10s ON / 5s OFF × 3 rounds = 45s → 5s ON / 2s OFF × 4 rounds ≈ 26s (~30s target)
- Changed from cancel-on-mid-sequence to full-sequence-run (pump OFF alert now works)

### Buzzer FSM rewrite
- Removed the mid-sequence cancel safety check that was killing pump OFF alerts
- Added `alertDirection` to track what event triggered the buzzer
- Alert now runs full 4 rounds regardless of pump state changes

## Final Session: Hardware Swap + Full Documentation

### Root Cause of GPIO33 Always-ON
Old 1ch relay module had NO optocoupler. Transistor-based module:
1. Got 12V on VCC (should be 5V) — may have damaged it
2. Was active-HIGH (not active-LOW as expected)
3. Even with correct wiring, module LED stayed ON permanently

### Solution
Replaced with proper 2ch optocoupler relay module (active-LOW, JD-VCC jumper ON).
Wiring: ESP32 5V→VCC, GND→GND, GPIO33→IN1.

### Also Fixed
- pinMode(OUTPUT) before digitalWrite(HIGH) = LOW glitch on ESP32 init
  -> Reordered to digitalWrite first in both bootRelaySafety() and Task3
- V0 Stop now clears relayState[] array so LED/buzzer turn off

### Final Test: All Good
- Module LED OFF at power-up
- Buzzer self-test 3 beeps
- Pump LED follows manual
- Buzzer alerts on pump state change (5s/2s x 4)
- V0 Stop turns everything OFF
